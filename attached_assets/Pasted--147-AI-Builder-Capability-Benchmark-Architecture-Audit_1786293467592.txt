#147 - AI Builder Capability Benchmark & Architecture Audit

What & Why

The AI Builder is the core competitive advantage of BirdFlow. This task establishes the first comprehensive benchmark of its real-world capabilities by testing the complete design workflow from a customer’s perspective.

Rather than only checking whether the AI can generate a website, this benchmark evaluates whether it can behave like an experienced web designer that can:

* Understand vague and detailed design requests
* Plan an entire website before building
* Build complete multi-page websites
* Maintain design consistency
* Create custom components when necessary
* Edit existing websites without breaking them
* Apply global design changes
* Create responsive layouts
* Generate SVG illustrations and decorative elements
* Apply motion and interactions
* Review and critique its own work
* Recover from mistakes
* Operate reliably over long conversations

The benchmark also identifies whether failures originate from:

* AI reasoning
* Missing tools
* Schema limitations
* Component architecture
* Context limitations
* Rendering limitations
* Builder UX
* Prompt design

The resulting audit becomes the foundation for future AI Builder improvements.

⸻

Success Criteria

A realistic psychologist clinic website is created entirely through the AI assistant using only natural language.

The audit evaluates every major capability of the AI Builder—not only generation, but also editing, redesigning, reviewing, repairing and maintaining the website.

A detailed benchmark report is written to:

Important Rules

* Do not manually edit the website. All creation and modifications must be performed through the AI assistant using natural language.
* Log every prompt, tool invocation (where visible), AI action, and resulting change.
* Distinguish between AI failures and platform/tooling limitations—do not mask architectural issues with prompt tweaks.
* Evaluate both the final visual result and the correctness of the AI’s planning, tool selection, and editing process.
* Prefer existing components when appropriate; create custom components only when they provide a clear advantage or when existing primitives cannot satisfy the requested design.
* Preserve design consistency across the entire website during every edit, and verify that unrelated pages are not unintentionally modified.
* This benchmark is an evaluation only. No AI Builder implementation code should be changed during this task.
