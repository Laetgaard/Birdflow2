# Birdflow — Full Onboarding System Architecture Audit

I want to fully redesign and finish Birdflow's onboarding system, but DO NOT implement or change anything yet.

First, inspect the current Birdflow codebase and give me the technical information needed to create a professional implementation plan.

The goal is to eventually support two complete onboarding paths that both end in the same Birdflow website builder.

---

# TARGET EXPERIENCE

Birdflow should have two primary onboarding paths.

## Path A — "I already have a website"

The practitioner enters the URL of their existing website.

Birdflow should then:

1. Crawl the website.
2. Discover relevant internal pages.
3. Extract:

   * page structure
   * navigation
   * headings
   * paragraphs
   * services
   * pricing
   * contact information
   * opening hours
   * team members
   * testimonials where relevant
   * images
   * logos
   * brand colors
   * typography/style information where possible
   * buttons and CTAs
   * forms
   * booking links/components
   * SEO metadata where relevant
4. Understand the site's information architecture.
5. Determine what content should be transferred versus ignored.
6. Ask the user only about information that:

   * could not be extracted
   * is ambiguous
   * is missing
   * needs confirmation
7. Recreate the website inside Birdflow.
8. Preserve the original site's visual identity as closely as reasonably possible.
9. Convert the recreated site into Birdflow's native editable website structure.
10. Replace incompatible functionality with Birdflow-native functionality where appropriate, particularly:

    * booking
    * forms
    * contact handling
    * payments if relevant
11. Run quality checks.
12. Let the user review the result.
13. Make every normal part of the website editable in the Birdflow builder afterward.

The important requirement is:

**The result must not simply visually look like the original website. It needs to become a real Birdflow website using the same builder/component/data architecture as websites created natively in Birdflow.**

---

# Path B — "I don't have a website"

If the practitioner does not already have a website, Birdflow should guide them through an intelligent onboarding interview.

The onboarding should collect enough information to create a professional website rather than a generic AI template.

Information will likely include:

### Business

* business/practice name
* practitioner name
* practitioner type
* location
* contact details
* target audience
* specializations
* years of experience
* credentials
* languages
* opening hours

### Services

For each service:

* name
* description
* duration
* price
* physical/online
* target client
* booking availability

### Positioning

* what makes their practice different
* therapeutic approach
* values
* desired perception
* important messages
* client problems they help solve

### Website goals

* booking
* lead generation
* information
* trust building
* selling services
* other goals

### Pages

Potential pages:

* home
* about
* services
* individual service pages
* pricing
* contact
* FAQ
* booking
* articles/resources if needed

But Birdflow should intelligently determine which pages are actually necessary.

### Content

The AI should generate professional:

* headings
* body copy
* CTAs
* service descriptions
* trust sections
* FAQs
* about content
* SEO titles/descriptions where appropriate

It should avoid generic AI copy.

### Branding/design

Collect preferences such as:

* desired feeling
* style
* colors
* existing logo
* colors to avoid
* imagery preference
* typography preference
* modern/classic/minimal/warm/etc.
* examples/reference websites if available

The user should not need to understand professional design terminology.

Questions should therefore be visual and understandable wherever possible.

### Images

The onboarding should determine:

* whether they have their own images
* whether uploaded images should be used
* which images belong to which content
* whether suitable stock/generated imagery is required

### Features

Determine whether the site needs:

* booking
* forms
* payment
* products
* team members
* testimonials
* newsletter
* contact form
* external links
* etc.

Then Birdflow should generate a complete website that is immediately editable inside the normal Birdflow builder.
