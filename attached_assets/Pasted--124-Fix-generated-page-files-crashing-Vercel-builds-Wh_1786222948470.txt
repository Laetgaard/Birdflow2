# #124 — Fix generated page files crashing Vercel builds

## What & Why

Birdflow publishing still fails for some websites even after adding `// @ts-nocheck` to the generated `ComponentRenderer.tsx`.

The reason is that Birdflow generates multiple TypeScript files during publishing.

The builder flow is roughly:

```text
Builder component data
        ↓
Birdflow publisher
        ↓
Generate standalone Next.js project
        ↓
Generate app/[page]/page.tsx files
        ↓
Generate ComponentRenderer.tsx
        ↓
Vercel next build
        ↓
Published customer website
```

The previous fix only protected the generated `ComponentRenderer.tsx`.

Generated page files such as:

```text
app/behandlinger/page.tsx
app/om-mig/page.tsx
app/kontakt/page.tsx
```

still contain baked-in component JSON/data that TypeScript validates independently.

A generated value such as:

```ts
alignment: "center"
```

may be inferred as:

```ts
string
```

while Birdflow's `ComponentData` type expects:

```ts
"center" | "left" | "right" | undefined
```

This causes `next build` on Vercel to exit with code 1 even though the website works correctly in the Birdflow builder preview.

Example failure:

```text
./app/behandlinger/page.tsx:274:17

Type error:
The types of 'props.alignment' are incompatible between these types.

Type 'string' is not assignable to type
'"center" | "left" | "right" | undefined'.
```

## Goal

Generated page files must not fail publishing because of TypeScript inference differences in machine-generated component data.

This task is a publishing reliability hotfix.

Do not redesign the entire component typing system in this task.

---

## Implementation

### 1. Update `generatePageFile()`

File:

```text
server/publisher/templates.ts
```

Find:

```ts
generatePageFile()
```

around the current page-template generator.

The returned file must begin with:

```ts
// @ts-nocheck
```

It must be the very first line of every generated page file.

Change the template from approximately:

```ts
return `${componentsImport}
```

to:

```ts
return `// @ts-nocheck
${componentsImport}
```

Use the same approach already used by:

```ts
generateComponentRenderer()
```

Do not add the comment conditionally.

Every generated Next.js page should receive it.

### 3. Add generator smoke test

File:

```text
tests/generator-smoke.test.ts
```

Add a regression test for `generatePageFile()`.

The test should generate a normal page and assert:

```ts
expect(output.startsWith("// @ts-nocheck")).toBe(true);
```

Also ensure the comment appears before imports.

Example expected beginning:

```ts
// @ts-nocheck
import ...
```

Not:

```ts
import ...
// @ts-nocheck
```

## Important constraints

Do not solve this by changing the global TypeScript configuration.

Do not disable TypeScript checking for the Birdflow application itself.

Do not weaken the builder's own `ComponentData` types.

The change applies only to machine-generated customer-site files produced by the publishing system.

Do not manually special-case:

```text
alignment
```

The underlying issue can happen with any literal-union prop generated as plain JSON.

The purpose of the hotfix is to make generated page files resilient to this entire class of TypeScript inference errors.
